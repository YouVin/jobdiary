## 1. 문제

props drilling·co-location 기준(데이터는 가까이, drilling 2~3단계를 넘으면 구조 다시 보기, 넘겨주기만 하는 중간 컴포넌트 점검)으로 웹앱을 점검했다.
단계 옮기기 `onMove`가 페이지(BoardClient·DashboardClient)에서 상세 패널 트랙까지 4단계를 내려가고, 그중 ProcessSection은 받은 `onMove`를 쓰지 않고 넘기기만 했다.
원인은 "화면에 먼저 반영하는 단계 변경"(`useStageMove`, React `useOptimistic`)이 페이지 컴포넌트 두 곳에 있어서, 지원 데이터가 스토어 버전과 먼저 반영한 버전 두 벌이 된 것이다.
그래서 옮기는 곳마다 props로 받아야 하고, 기록 저장(DiaryComposer)과 전형 절차 트랙(useProcessStep)은 "어느 쪽이 최신인지"를 각자 따로 다룬다.
쓰레드 홍보(2026-12-03~04)를 5일 앞두고, 이 경로는 카드 끌기·점 누르기·상세 패널이 모두 지나는 가장 많이 쓰는 동작이다.
