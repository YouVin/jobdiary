# 003. 회사 정보의 공고 내용을 익스텐션이 공고 페이지에서 읽어 오기

| 항목 | 내용 |
|---|---|
| 상태 | **결정** (구현 #238, 팝업 디자인·아이콘 #239) |
| 날짜 | 제안·결정 2026-11-25 |
| 관련 이슈·PR | #238, #239 (이전: #232 이미지 넣기, #237 강점이 비는 문제) |
| 결정한 사람 | YouVin |

## 1. 문제

- 채용 공고 본문은 이미지인 경우가 많아 "공고 캡처 붙여넣기"(#232)로 회사 정보를 만들었다.
- 캡처 방식은 결과가 사용자가 무엇을 얼마나 잘 캡처했는지에 달려 있다. 실제로 페이지 전체를 한 장으로 줄인 캡처는 글씨가 작아 강점이 비었고, 상세 근무지는 본문이 아니라 위쪽 요약 칸에 있어 "서울"만 나왔다(#237).
- 사용자가 캡처하지 않고, 공고 페이지 자체를 읽어 만들고 싶다.

## 2. 지금 숫자 (2026-11-25, 사용자가 준 공고 3개를 한 번씩 받아 확인)

| 항목 | 잡코리아 (2개) | 사람인 (1개) |
|---|---|---|
| 상세 근무지 | 페이지 구조화 데이터(JSON-LD `JobPosting.jobLocation`)에 정확한 주소 ("서울 강남구 도산대로56길 5 (청담동) 지하1층,1층") | 본문의 근무조건 칸 글자 |
| 공고 본문 위치 | 같은 사이트 별도 페이지 `/Recruit/GI_Read_Comt_Ifrm?Gno=…` | `/zf_user/jobs/relay/view-detail?rec_idx=…` |
| 본문 형태 | 글 공고 1,421자 / 이미지 공고 이미지 1장 | 글 454자 + 이미지 1장 |
| 본문 이미지 원본 | **860×5,017px PNG, 640KB** (사용자 캡처보다 훨씬 선명) | WebP 216KB |
| 이미지 서버 | `file2.jobkorea.co.kr` — **익스텐션 권한 밖**, CORS 허용 안 함 | `static.saraminimage.co.kr` — CORS `*` 허용 |
| 익스텐션 지금 권한으로 페이지·글 읽기 | 됨 (`https://www.jobkorea.co.kr/*`) | 됨 (`https://*.saramin.co.kr/*`) |

### 원티드 (2026-11-25 추가, 사용자 요청)

| 항목 | 원티드 (공고 1개 확인) |
|---|---|

## 3. 선택지

방향(사용자 결정 2026-11-24): 서버가 공고 페이지에 직접 접속(A)이 아니라 **익스텐션이 공고 페이지를 읽는다(B)**. 채용 사이트는 서버 자동 접속을 막는 경우가 많고(슈퍼루키 403), 익스텐션은 기존 원칙("사용자가 보는 사이트를 사용자 브라우저에서 읽는다")과 같다.

남은 문제는 잡코리아 본문 이미지(다른 서버, CORS 없음)를 가져오는 방법이다.

| | 1. 익스텐션 권한에 이미지 서버 추가 | 2. 필요할 때만 권한 요청(선택 권한) | 3. 우리 서버가 이미지 파일만 대신 받기 |
|---|---|---|---|
| 방식 | manifest `host_permissions`에 `file*.jobkorea.co.kr` | `optional_host_permissions` + `chrome.permissions.request` | Edge Function이 허용 목록의 이미지 주소만 받아 브라우저에 넘기고, 브라우저가 잘라 분석 |
| 장점 | 단순 | 기존 사용자 영향 없음 | **익스텐션 권한 변경 없음** |
| 단점 | 업데이트 시 크롬이 익스텐션을 끄고 권한 재승인을 받는다(이탈 위험) | 권한 요청은 익스텐션 화면에서 사용자가 직접 눌러야 해 흐름이 복잡 | 서버가 아무 주소나 받지 않게 허용 목록·https·크기 제한 필요(SSRF 방지) |

## 4. 결정

**AI 추천:** 3. 권한 경고가 없고, 서버가 하는 일이 "사용자가 누른 공고의 공개 이미지 파일 받기"로 좁다.

**내 결정:** 3으로 간다. 익스텐션을 업데이트하는 김에 팝업 디자인을 웹앱과 같은 토스 느낌으로 통일하고(배치는 비슷하게 유지), 아이콘도 새 로고로 바꾼다(#239).

함께 정한 것:
- 근무지는 AI가 읽은 값보다 페이지의 정확한 주소(구조화 데이터)를 우선한다.
- 글 공고는 이미지 읽기 없이 글로 분석한다(더 싸고 정확).
- 익스텐션이 없거나 공고 주소가 저장되지 않은 지원은 지금처럼 캡처·글 붙여넣기를 쓴다.

## 5. 성공 기준과 검증 방법

- 사용자가 준 공고 3개에서: 잡코리아 2개는 상세 근무지 주소가 정확히 나옴, 글 공고는 이미지 없이 분석, 이미지 공고는 원본 해상도로 강점이 2개 이상
- 이미지 대신 받기: 허용 목록 밖 주소·http·이미지가 아닌 응답·크기 초과는 거절(단위 테스트)
- 익스텐션 권한(manifest) 변경 없음 — 출시 검증 스크립트로 확인
- 비용: 글 공고 1원 안팎, 이미지 공고 2원 안팎(실측)
