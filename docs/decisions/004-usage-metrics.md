# 004. 사용량 지표를 DB 방문 기록 + Vercel Web Analytics로

## 1. 문제

쓰레드에 홍보 글을 올릴 예정인데, 지금은 몇 명이 가입했고 그중 몇 명이 다시 오는지, 어디서 들어왔는지 알 수 없다.
홍보 효과와 "사람들이 실제로 쓰는가"를 숫자로 말할 근거가 없다.

## 2. 지금 숫자

| 지표 | 값 | 잰 방법 |
|---|---|---|
| 가입·지원·회사 정보 수 | 볼 수 있음(따로 모아 둔 곳은 없음) | `auth.users`·`applications`·`application_analyses` 직접 조회 |
| 재방문(활성 사용자) | 볼 수 없음 | 로그인 세션이 오래 유지돼 `last_sign_in_at`이 방문을 뜻하지 않음 |
| 유입 경로·로그인 전 방문자 | 볼 수 없음 | 수집 장치 없음 |

## 3. 선택지

| | A. DB 집계만 | B. DB 집계 + 방문 날짜 기록 | C. B + Vercel Web Analytics |
|---|---|---|---|
| 요약 | 있는 표만 집계 | 로그인 사용자의 방문 날짜를 하루 한 줄 저장 | C = B에 쿠키 없는 페이지 조회 통계 추가 |
| 장점 | 새로 모으는 정보 없음 | 재방문율 계산 가능, 외부 서비스 없음 | 쓰레드 유입·가입 안 한 방문자까지 보임 |
| 단점 | 재방문·유입 모름 | 유입 경로 모름 | 외부 처리(Vercel, 이미 호스팅 위탁 중) 범위 늘어남, 무료 한도 있음 |
| 비용·시간 | SQL 파일 하나 | 표·함수·웹앱 호출 | + 패키지 1개(2.0.1), 대시보드에서 켜기 |

## 4. 결정

**AI 추천:** C. 홍보 효과를 보려면 유입 경로가 필요하고, Vercel은 이미 호스팅을 위탁한 곳이라 새 업체가 늘지 않는다. 방문 기록은 "그날 왔다"만 남겨 모으는 정보를 최소로 한다.

**내 결정:** C로 간다. (2026-11-25, 선택지 중 추천안을 골랐다. 이유는 본인이 보충한다.)

## 5. 성공 기준과 검증 방법

- 기준: 운영 반영 다음 날 `usage_metrics.sql`의 오늘 활성 ≥ 1, Vercel Analytics에 페이지 조회가 보인다. 주소에 쿼리가 남지 않는다.
- 확인 방법: 테스트 `usageMetrics.test.mjs`, 브라우저 검증 `verify-release-browser.mjs`(동의 전 0번·동의 뒤 1번·새로고침 1번), 운영에서 SQL·대시보드 확인.
