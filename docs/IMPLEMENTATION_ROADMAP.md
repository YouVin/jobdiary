## 3. 모노레포로 이동 — 완료

기존 `YouVin/jobdiary`를 통합 저장소로 사용하는 방향을 기본안으로 삼는다.

```text
jobdiary/
  apps/
    web/
    extension/
  packages/
    shared/       # 실제 공통 계약 추출은 5단계에서 진행
  docs/
  package.json
```

- 기존 두 저장소의 커밋 이력을 보존하는 이전 방식을 적용한다.
- npm workspaces를 구성하고 앱별 개발·테스트·빌드 명령을 유지한다.
- CI, 작업 지침, 문서·스크립트의 상대경로, 공개 문서 게시 경로를 함께 점검한다.
- 웹앱 호스팅의 빌드 경로와 익스텐션 ZIP 생성 경로를 확인한다.
- 환경 설정과 기존 외부 서비스 연결을 유지한다. 웹앱과 익스텐션의 버전·릴리스는 각각 관리한다.
- 이 단계에서는 파일 이동과 설정 변경에 집중하고 새 기능 동작을 추가하지 않는다.

완료 기준: 이전 전 기준 검증이 새 구조에서도 통과하고, 두 앱을 각각 실행·빌드할 수 있다.
운영 배포와 Chrome 웹스토어 제출은 이 단계의 완료 조건에 포함하지 않는다.

## 5. 공통 연동 계약과 지원 이력 동기화 — 구현·자동 검증 완료

- 실제 양쪽 코드에서 공통으로 쓰는 메시지 타입·검증·공고 식별 규칙만 shared로 추출한다.
- 공고 URL/ID가 실제 저장·조회·전달 경로에 보존되는지 먼저 확인한다.
- 웹앱 가져오기 성공·로그인 후 조회·지원 추가/수정/삭제 시 비교용 목록을 갱신한다.
- 웹앱에서 허용된 메시지로 최소 비교 정보만 전달한다. 인증 토큰·메모·일기는 보내지 않는다.
- 마지막 동기화 시각, 계정 변경·로그아웃, 캐시 삭제·실패 처리를 정의하고 검증한다.
- 웹앱이 닫힌 동안의 다른 기기 변경은 즉시 알 수 없다는 제한을 반영한다.

## 6. 지원 이력 자동 표시 — 구현·자동 검증 완료

- 잡코리아 → 사람인 순서로 실제 공고 식별과 목록·상세 화면 표시를 검증한다.
- 원티드는 현재 지원내역에 공고 ID/URL이 없으므로 정확한 식별 방법을 조사한 뒤 지원 범위를 결정한다.
- 같은 사이트·같은 공고 ID에만 확정 배지를 표시한다. 회사명·제목 유사성으로 지원 사실을 단정하지 않는다.
- 마감일이나 이력의 나이만으로 비교 대상에서 제외하지 않는다. 지원취소 이력은 구분한다.
- 기본 표시는 공고 제목/링크 옆의 작은 배지로 한다. 버튼 위 표시는 구조가 확인된 화면에 한정한다.
- 현재 페이지의 공고만 비교하고, 변경된 영역만 추가 처리한다. 공고별 추가 네트워크 조회는 하지 않는다.
- 중복 배지, 반복 검사, 숨겨진 탭의 불필요한 작업, 제거된 DOM 참조의 누적을 방지한다.
- 자동 표시 끄기를 제공하고 다중 탭·긴 목록·무한 스크롤에서 CPU/메모리와 화면 영향을 측정한다.
- 수동 비교 버튼은 자동 기능의 필요성과 검증 결과를 보고 보조 기능으로 판단한다.

완료 기준: 지원 범위가 명시되고, 오표시·화면 깨짐·반복 처리 없이 성능 검증을 통과한다.
3개 사이트의 모든 종류의 화면을 지원한다고 검증 전에 약속하지 않는다.

2026-11-04: 잡코리아·사람인 공고 링크/단일 상세 제목에 정확한 ID 기반 지원·취소 배지를 구현했다.
자동 표시 설정·동기화 현황과 이력 갱신 진입을 추가했다. 원티드는 식별 정보 부족으로 보류한다.
