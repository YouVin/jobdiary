# 마감일 수집 작업 상태

상위 이슈: [#60](https://github.com/YouVin/jobdiary-extension/issues/60)
작업 이슈: [#63](https://github.com/YouVin/jobdiary-extension/issues/63)
브랜치: `feat/63-application-deadline`

## 구현 상태

- 선택적 마감일 원문/전달 타입, 엄격한 날짜 검증 및 어댑터
- 기존 로컬 저장/웹앱 응답 경로의 선택적 `deadlineAt: YYYY-MM-DD` 전달
- 사람인 PC 수집 후 모바일 지원현황 첫 응답의 마감일 보충
- 잡코리아 지원 행의 `.apply-progress .extra` 원문 추출
- 잡코리아 공개 공고 상세의 메타 설명·JSON-LD를 교차 검증한 마감일 보충
- 팝업의 마감일 확인 건수 또는 조회 실패 안내

**모바일 요청이 PC Chrome의 실제 로그인 상태로 성공하는지는 아직 미검증이다.**
코드와 제공 HTML 기반 테스트를 통과한 상태이며, 실제 성공이 확인된 기능으로
설명하지 않는다. 버전은 1.0.3으로 유지 중이며 출시 준비 완료 상태가 아니다.

## 사이트별 근거

| 사이트 | 확인된 실제 HTML | 처리 |
| --- | --- | --- |
| 사람인 PC | 네 표본 모두 `.date_end`가 비어 있음 | PC 행에서 날짜를 추정하지 않음 |
| 사람인 모바일 | `/apply/state`의 `.box_apply` 제목에 `(~2026-11-01)`, 다른 카드에는 `(마감)` 표시 | 연도 포함 날짜만 추출해 PC 지원에 보충 |
| 잡코리아 | 지원현황 `(~10/31)` + 연결 공고의 메타 설명/JobPosting.validThrough | 공고 ID와 두 날짜가 일치할 때만 연도 포함 날짜 보충. 상시 제외 |
| 원티드 | 제공 행에 지원일·회사·포지션·상태 등이 있지만 마감일/공고 링크 없음 | 마감일 생략 |

사람인의 삭제 안내 `TipTxt`는 방금 지원한 행에도 있으므로 이 문자열만으로
삭제 여부를 단정하지 않는다. 마감여부 필터 `recruit_status=closing`도
각 행의 정확한 마감일을 알려주는 값은 아니다.

## 사람인 PC → 모바일 보충 경로

1. 기존 PC 지원현황 수집·페이지 순회를 먼저 완료한다.
2. 결과가 있을 때 content script가 내부 메시지 `SARAMIN_MOBILE_DEADLINES`를 보낸다.
3. service worker가 고정된 주소
   `https://m.saramin.co.kr/apply/state?local_code=&appmode=need_login`에 한 번 요청한다.
4. HTML을 content script에서 DOMParser로 파싱한다. 가져온 HTML을 화면에 삽입하거나
   스크립트를 실행하지 않는다.
5. `.apply_condition .status_list .box_apply` 안에서
   `input[name="recruitapply_idx"]`, `a.name_job[href]`의 `rec_idx`,
   `a.name_job .txt`의 마지막 `(~YYYY-MM-DD)`를 읽는다.
6. PC 행의 `externalId`와 공고 URL의 `rec_idx`가 **둘 다** 일치할 때만 날짜를 보충한다.
   회사명/제목/배열 순서로 지원 건을 추정하지 않는다. 동일 키에 상충하는 날짜가 있으면 생략한다.
7. 공통 어댑터에서 검증한 후 기존 슬롯에 저장하고 팝업에 결과를 응답한다.

현재 모바일 페이지네이션·추가 로딩 방식은 제공된 HTML에 없다. 확인되지 않은
파라미터로 순회하지 않고 **첫 요청 HTML에 있는 일치 항목만** 보충한다.
PC 필터를 모바일 조회 조건으로 변환하지 않으며, PC에서 수집된 건 밖의 모바일
지원은 추가 저장하지 않는다. 추천공고 `.recomm_cont`는 수집하지 않는다.

요청 URL을 메시지로 받지 않고, 동일 확장의 사람인 PC 지원현황 최상위 탭에서 온
메시지만 허용한다. 다른 사이트·팝업·하위 프레임은 거부한다. 기존 host permission의
`https://*.saramin.co.kr/*` 안에서 처리하며 주입 경로/권한을 추가하지 않는다.

브라우저가 허용하는 기존 로그인 상태로 요청(`credentials: include`)하지만 쿠키나
토큰의 값을 코드로 읽거나 보관하지 않는다. 재로그인이나 인증 우회를 구현하지 않는다.
리다이렉트·네트워크 오류·5초 시간 초과·HTML 아닌 응답·2백만 자 초과·지원 카드 없는
응답은 보충 실패로 처리한다. **모바일 조회가 실패해도 PC 지원내역은 저장한다.**
모바일 원문 HTML은 저장·로그·웹앱 응답에 포함하지 않는다.

## 날짜와 상태

### 잡코리아 공개 공고 교차 확인 (2026-10-22)

지원현황에서 연결된 실제 공고의 공개 원본 HTML을 로그인 없이 읽어 확인했다.

| 공고 | 메타 description의 마감일 | JobPosting.validThrough | 판단 |
| --- | --- | --- | --- |
| [50200844](https://www.jobkorea.co.kr/Recruit/GI_Read/50200844) | 2026.10.31 | 2026-10-31T23:59 | 날짜 일치 |
| [50064583](https://www.jobkorea.co.kr/Recruit/GI_Read/50064583) | 2026.10.28 | 2026-10-28T23:59 | 날짜 일치 |
| [49885752](https://www.jobkorea.co.kr/Recruit/GI_Read/49885752) | 상시채용 | 2027-08-30T15:00 | 구조화 날짜가 있어도 생략 |

따라서 validThrough 하나만으로 날짜를 판정하지 않는다. `meta[name="description"]`의
명시된 `마감일 : YYYY.MM.DD`와 `script[type="application/ld+json"]`의 JobPosting 날짜가
같고, `url`의 공고 ID 및 `identifier`의 JobKorea ID가 요청 공고와 모두 같아야 보충한다.
페이지 스크립트를 실행하거나 Next.js 내부 상태를 해석하지 않는다.

PC 지원현황 수집 후 해당 지원 공고의 `/Recruit/GI_Read/{숫자ID}`만 공개 조회한다.
쿠키를 보내지 않으며 리다이렉트를 따라가지 않는다. 같은 공고는 한 번 조회하고,
최대 10개 공고·동시 2건·요청당 4초로 제한한다. 나머지 지원은 날짜 미확인으로 유지한다.
PC 목록의 `(상시)`/채용 시 마감 표시는 추가 조회에서 제외한다. 원문에 명시된 날짜가
있는 공고도 조기 마감될 수 있으며, 이는 기업의 공식 불합격 통보가 아니다.

잡코리아의 공개 HTML 수신은 확인했지만 확장 content script의 실제 브라우저 요청은
미검증이다. 비www 페이지에서 www 리다이렉트가 필요한 경우에도 날짜 보충만 실패 처리한다.
권한과 content script 주입 범위는 유지하고 기존 지원내역은 조회 실패와 무관하게 저장한다.

- 연도 없는 날짜에 지원일 연도나 현재 연도를 붙이지 않는다.
- `(마감)`·상시채용·무효 날짜는 정확한 날짜를 알 수 없으므로 생략한다.
- 공고가 마감되면 과거에 표시된 실제 날짜가 없어질 수 있다. 현재 보충은 재수집 시
  슬롯 교체라는 기존 계약을 따르므로 과거 마감일을 별도 이력으로 보존하지 않는다.
- 익스텐션에서 마감일을 이유로 상태를 변경하지 않는다.
- 웹앱의 기존 지원은 재수집으로 갱신하지 않으므로 기존 카드의 마감일도 자동 보충하지 않는다.
- 전체 복사는 기존 여섯 열을 유지한다. 마감일은 웹앱 전달용 선택 필드다.

## 검증

2026-10-22: `npm test` 18개 파일·166개 테스트 통과, `npm run build` 타입 검사와
프로덕션 빌드 통과. 실제 Chrome 로그인 환경은 아직 미검증이다.
잡코리아 공개 원본 HTML 세 건을 임시 파일에 내려받아 구현 파서를 직접 적용한
추가 검증도 3건 통과했다. 두 날짜는 각각 2026-10-31/2026-10-28, 상시채용은
undefined를 반환했다. 이 일회성 검증 파일은 제거했고 CI에는 개인정보 없는 고정 테스트만 둔다.

개인정보가 있는 첨부 원문은 저장소에 복사하지 않았다. 테스트는 필요한 DOM 구조만
재현하고 회사·지원 ID·추적 정보·이력서 링크 등을 예시값으로 대체했다.

- 날짜 형식·달력 유효성·무효/불명확 날짜 생략
- PC와 모바일 두 ID 일치, 상충 중복, 마감 표시, 추천공고 제외
- 고정 URL/요청자 검증, 실패·시간 초과 시 PC 결과 보존
- 잡코리아 공고 ID/표시 날짜/구조화 날짜 교차 검증, 상시채용의 가짜 마감 분류 방지
- PC 수집→background 모바일 요청→어댑터→저장→웹앱 응답의 통합 테스트
- 실제 로그인 환경·페이지네이션·웹앱 신규 가져오기는 수동 확인 필요

## 사용자가 확인할 순서

1. 빌드 후 `chrome://extensions`에서 테스트 확장을 새로고침한다.
2. 사람인 또는 잡코리아 PC 지원현황을 새로고침하고 수집한다.
3. 팝업의 “마감일 N건 확인” 또는 “마감일을 확인하지 못했어요”를 확인한다.
4. 제공 표본과 같은 지원이 모바일 첫 응답에 있으면 1건 이상 확인되는지 살펴본다.
   “0건 확인”은 응답 카드는 있지만 PC와 일치하는 명시 날짜를 찾지 못했다는 뜻이다.
5. 실패 안내가 나오면 PC 내역은 정상 저장됐는지 확인한다. 모바일에서 별도 로그인이
   필요한지 또는 서버 응답이 렌더링 전 HTML인지 추가 검증한다.
6. 웹앱에 처음 추가하는 지원의 마감일을 확인한다. 기존 카드가 갱신되지 않는 것은 계약상 정상이다.

빌드가 만드는 `release/crx-jobdiary-extension-1.0.3.zip`은 개발 중 소스로 재생성된
검증 산출물이다. 기존 출시본과 같은 이름이므로 새 출시 버전 결정 전 웹스토어에
업로드하지 않는다. 정책·스토어 설명의 변경도 아직 공개 배포되지 않았다.
