# 홈 통계 대시보드

관련 이슈: #146~#150. 계산은 `apps/web/src/utils/applicationStats.ts`, 테스트는 `apps/web/tests/applicationStats.test.mjs`.

## 계산 기준 (#146)

- 통계는 검색·필터와 무관하게 항상 전체 지원 내역으로 계산한다.
- 날짜는 화면 표시(`formatDate`)와 같이 저장된 ISO 값의 UTC 날짜를 쓴다. 날짜만 있는 값(`YYYY-MM-DD`)은 그대로 쓰고, 해석할 수 없는 값은 계산에서 뺀다.
- 오늘은 `getTodayInKorea()`의 한국 날짜다. 이번 주는 그 주 월요일부터 오늘까지다.

| 값 | 기준 |
|---|---|
| 전체 지원 | 지원 내역 수 (지원취소 포함) |
| 지원한 기업 | 회사명의 유니코드 NFKC, 공백 제거, 소문자 정규화 후 고유 개수 |
| 진행 중 | 지원완료·서류통과·면접예정·면접완료 |
| 서류 통과 | 서류통과·면접예정·면접완료·합격 (서류 단계를 넘긴 건수) |
| 종료 | 합격·탈락·지원취소 |
| 서류 통과율 | 서류 통과 ÷ (전체 − 지원취소). 분모가 0이면 표시하지 않는다 |
| 마감 자동 탈락 | 탈락이면서 `statusSource`가 `deadline`인 건수 |
| 지원 경로 | 플랫폼별 건수·비율. 건수순, 같으면 사람인·잡코리아·원티드·직접입력 순. 0건도 포함 |
| 다가오는 일정 | 종료되지 않은 지원의 면접일·공고 마감일 중 오늘 이후. 날짜순, 같은 날이면 면접 먼저 |
| 최근 지원 | 지원일 최신순, 같은 날이면 최근 수정순 |

지원취소는 사용자가 지원을 거둔 경우라 전형 결과가 아니다. 그래서 전체 수에는 넣고 통과율 분모에서는 뺀다.

## 화면 구성 (#147)

- 홈(`/`)은 통계 대시보드, 지원보드(`/board`)는 주간 보기(타임라인·기다리는 목록)와 보드 보기(검색·필터·7단계 칸반)다([BOARD](BOARD.md)). 헤더 탭으로 오간다. 데스크톱은 로고 옆 탭, 모바일(767px 이하)은 헤더 아래 전체 폭 탭 줄이며 계정 설정·로그아웃은 아이콘만 보인다(접근성 이름 유지).
- 지원보드 탭 옆 숫자는 전체 지원 수다. 처음 조회가 끝나기 전에는 0으로 보이지 않도록 숨긴다.
- 지원 내역 조회는 `useApplicationsLoader`를 두 페이지가 함께 쓴다. 페이지에 들어올 때마다 다시 조회하되, 이미 조회한 세션이면 이전 목록을 바로 보여주고 뒤에서 갱신한다. 탭을 옮길 때마다 스켈레톤이 깜빡이지 않게 하려는 선택이며, 비용은 페이지 이동당 조회 1회다. 한국 날짜가 바뀐 뒤 화면으로 돌아오면 다시 조회해 마감 자동 탈락을 반영한다.
- 익스텐션의 `?import=1` 자동 가져오기, 가져오기 버튼, 결과 알림은 홈에 둔다. 익스텐션이 여는 주소(`/?import=1`)는 바뀌지 않는다.
- 1줄: 전체 지원 수·전형 현황 카드(7/12)와 지원 기록 업데이트 카드(5/12). 태블릿·모바일은 세로로 쌓는다.
  - 전형 현황 막대·범례는 칸반 컬럼과 같은 상태 토큰을 쓴다. 면접예정·면접완료는 같은 색이라 "면접" 하나로 묶는다. 색만으로 구분하지 않도록 범례에 이름·건수를 함께 쓰고, 막대에는 전체 건수를 읽는 접근성 이름을 둔다.
  - 지원 기록 업데이트는 익스텐션과 같은 platform 토큰(배경/글자)으로 사람인·잡코리아·원티드를 표시하고, 각 사이트의 지원현황 페이지를 새 탭으로 연다. 주소는 익스텐션 팝업 바로가기와 같다.
- 대표 숫자는 새 `display`(48/56) 타이포 토큰, 보조 숫자는 `heading-xl`을 쓴다. 아이콘 `download`, `arrow-right`를 추가했다.

## 다가오는 일정·최근 지원 (#148)

- 2줄: 다가오는 일정(7/12)과 최근 지원(5/12). 각 카드 머리에 지원보드 링크를 둔다.
- 다가오는 일정은 최대 4건, 나머지는 "외 N건"으로 알린다. D-day는 오늘이면 `D-DAY`, 면접은 브랜드 연한 색, 공고 마감은 회색 칩으로 구분하고 종류 글자("면접"/"공고 마감")를 함께 쓴다.
- 최근 지원은 4건, 회사명·플랫폼 배지·지원일·현재 상태(칸반과 같은 상태 점 색)를 보여준다. 상태 점 색은 `constants/status.ts`의 `STATUS_DOT_CLASS`를 칸반 컬럼 머리와 함께 쓴다.
- 두 카드의 행을 누르면 지원보드와 같은 상세 패널([BOARD](BOARD.md) #175)을 연다. 패널의 "정보 수정"에서 면접일 입력·상태 변경을 하고, 기록도 남길 수 있다. 수정 중 삭제되면 패널도 닫힌다. (처음에는 수정 모달이었다.)
- 빈 상태: 일정이 없으면 면접일·공고 마감일 입력 안내, 지원이 없으면 지원추가·가져오기 안내를 보여준다.

## 지원 경로별 비율 (#149)

- 3줄 전체 폭. 도넛(가운데 전체 지원 수)과 플랫폼별 건수·비율 목록. 비율은 소수 첫째 자리까지.
- 색은 플랫폼에 고정한다. 사람인·잡코리아·원티드는 익스텐션과 같은 platform 토큰의 글자색을 `chart` 키로 그대로 쓰고, 직접입력은 웹앱 전용 `platform.manual`(배지 `#F2F2F4`/`#71717A`, 차트 `#A1A1AA`)을 새로 정의했다. 이전에는 직접입력 배지가 사람인 배지 색을 빌려 써서 둘을 구분할 수 없었다.
- 사람인 진회색과 잡코리아 진한 빨강은 적색약 시뮬레이션에서 가깝게 보인다(팔레트 검사 CVD ΔE 6.7, 일반 시야 18.0). 그래서 목록에 이름·건수·비율을 항상 함께 쓰고 조각 사이에 바탕색 간격을 둔다. 색만으로 경로를 구분하지 않는다.
- 도넛 조각이나 목록 행에 마우스를 올리거나 행에 키보드 포커스를 두면 같은 경로를 강조하고 나머지 조각을 흐리게 한다. 조각에는 이름·건수 툴팁, 도넛에는 전체 건수를 읽는 접근성 이름을 둔다. reduced-motion이면 전환 효과를 끈다.
- 도넛은 데이터로 모양이 정해져 아이콘 파일로 만들 수 없다. 그래서 `src/components/charts/`에서만 SVG 작성을 허용하도록 `scripts/check-ui-style.mjs`를 바꿨다. 색은 그대로 토큰 클래스(`stroke-platform-*-chart`)만 쓴다.

## 마지막 가져오기 시각 (#150)

- 지원 기록 업데이트 카드 머리에 "마지막 가져오기 MM.DD HH:mm"(한국 시간)을 보여준다. 기록이 없으면 "가져온 기록 없음".
- 익스텐션 응답을 검증하고 저장까지 성공했을 때만 시각을 남긴다. 새 지원 없이 모두 건너뛴 경우도 확인은 끝난 것이라 성공으로 본다. 저장 실패·응답 오류·계정 변경으로 취소된 요청은 남기지 않는다.
- `lib/storage.ts`의 `loadLastImportAt`/`saveLastImportAt`로 `jobdiary:lastImportAt:<사용자 ID>` 키에 저장한다. 계정별 키라 다른 계정에는 보이지 않고, 이 브라우저에만 남는 편의 정보라 DB에 저장하지 않는다. 저장할 수 없는 환경(사생활 보호 모드 등)에서는 기록 없음으로 동작한다.
- 시안의 플랫폼별 증감(+2)은 가져오기 결과가 플랫폼별로 나뉘지 않아 넣지 않았다.

## 일기장 콘셉트로 재구성 (#158)

사용자 피드백: 첫 구현이 참고한 서비스 화면과 구조까지 비슷하다. 익스텐션 팝업의 흑백 일기장 콘셉트([EXTENSION_POPUP_DESIGN](EXTENSION_POPUP_DESIGN.md))를 이어 시안 v2로 재구성했고, 지원 경로 도넛은 사용자 요청으로 유지했다.

| 이전 (#147~#150) | 현재 |
|---|---|
| 전체 지원 수 숫자 타일 + 상태 막대 | 오늘의 일기장: serif 날짜(익스텐션과 같은 `Nov.` 월 약어), 현황 문장 요약, 수치 칩 |
| 사이트별 행이 있는 지원 기록 업데이트 카드 | 일기장 하단 한 줄: 마지막 가져오기, 사이트별 건수 칩(누르면 지원현황 새 탭), 가져오기 버튼 |
| 상태 막대·범례 | 전형 여정: 지원완료 → 서류통과 → 면접 → 합격, 끝난 지원(탈락·마감 자동·지원취소)은 아래 한 줄 |
| 일정 목록 | 날짜가 세로로 이어지는 타임라인, 오늘은 검정 D-DAY |
| (없음) | 이번 달 지원 달력: 월요일 시작, 날짜별 지원 건수를 4단계(`heat-1~4`)로 칠함. #193부터 회색→검정 단계 |

- 배치: 1줄 일기장 / 2줄 전형 여정(7) · 지원 경로(5, 목록 한 열) / 3줄 일정 · 최근 지원 · 달력(데스크톱 3열, 태블릿 2열+달력 전체 폭, 모바일 1열).
- 요약 문장: 지원 0건이면 시작 안내. 아니면 "지금까지 N건 지원했고, M건이 아직 소식을 기다리고 있어요." 가장 가까운 일정이 오늘이면 "오늘은 회사 면접이 있는 날이에요.", 아니면 "다음 일정은 D-n 회사 공고 마감이에요."를 덧붙인다.
- 달력은 읽기 전용이다(날짜 칸 말풍선은 #184). 칸은 버튼이 아니며 날짜별 건수를 접근성 이름으로 읽고 오늘 칸에 `aria-current="date"`를 둔다. 계산은 `getMonthCalendar`(지원일 UTC 날짜, 한국 오늘 기준)이며 윤년·월 길이를 처리한다.
- 날짜 글꼴은 익스텐션과 같은 시스템 serif(`font-diary`)이며 외부 폰트를 받지 않는다. 날짜 숫자에만 쓰고 본문은 Pretendard다.
- 숫자 타일용 `display` 타이포 토큰과 `OverviewCard`·`ImportCard`는 제거했다.

## Pretendard 통일과 전형 여정 간소화 (#161)

사용자 피드백: 글꼴은 Pretendard로 통일하고, 전형 여정은 숫자만 남겨 메인 느낌을 살린다. 다이어리 느낌은 구조를 바꾸지 않고 표현만 살짝 둔다.

- 날짜(`NOV.` 17)와 일정 타임라인 날짜의 serif를 없애고 Pretendard 굵은 숫자로 바꿨다. `font-diary` 글꼴 토큰은 제거했고 `diary-*`는 크기 토큰으로만 남는다.
- 전형 여정은 단계 이름과 숫자만 가운데 정렬로 보여준다. 단계별 보조 문구(결과 대기·서류 통과율·예정/완료·아직 없어요)와 하단 "여정을 마친 지원"(탈락·마감 자동·지원취소) 줄을 없앴다. 서류 통과율과 마감 자동 탈락은 일기장 수치 칩에 남아 있다. 단계 사이는 점선으로 잇는다.

## 달력 날짜 말풍선 (#184)

사용자 요청: 지원 달력 날짜에 마우스를 올리면 몇 건 지원했는지 바로 보이게 한다. 이전에는 브라우저 기본 툴팁(`title="N건 지원"`)이라 1초쯤 늦게 작게 떴고 터치 화면에서는 보이지 않았다.

- 지난 날짜·오늘 칸에 마우스를 올리면 바로 말풍선이 뜬다: "11월 20일 · 지원 2건"과 그날 지원한 회사 이름 최대 3곳(넘으면 "외 N건"). 지원이 없는 날은 "지원 없음". 미래 날짜는 말풍선이 없다.
- 터치 화면은 칸을 탭하면 뜨고 다른 곳을 누르면 닫힌다(#190부터 지원이 있는 날은 탭하면 말풍선 대신 회사 목록이 열린다). 칸에 `tabIndex={-1}`를 줘 탭(클릭)으로만 포커스를 받고, Tab 순서에는 넣지 않았다(한 달 30칸이 Tab 순서를 채우지 않게). 표시는 CSS `group-hover`/`group-focus`만 쓰고 JS 상태가 없다.
- 월·화 칸은 왼쪽, 토·일 칸은 오른쪽, 나머지는 가운데에 맞춰 390px에서도 카드 밖으로 나가지 않는다. 색은 `bg-text-primary`·`text-on-brand`, 그림자는 `shadow-float` 토큰이다.
- 화면 읽기 프로그램은 지금처럼 칸의 `aria-label`("11월 20일 지원 2건")로 읽고 말풍선은 `aria-hidden`이라 두 번 읽지 않는다. 회사 이름은 접근성 이름에 넣지 않았다.
- 데이터: `getMonthCalendar`의 `CalendarDay`에 `companies`(그날 지원한 회사 이름, 목록 순서)를 더했고 `count`는 그 길이다.

## 달력 날짜 → 회사 목록 → 기록 (#190)

사용자 결정: 상세 패널(기록 남기기·정보 수정)을 "달력과 회사 기록"에서 연다. 날짜를 누르면 그날 지원한 회사 목록이 열리고, 회사를 고르면 패널이 열린다.

- 지원이 있는 지난 날짜·오늘 칸은 버튼이다(`aria-pressed`로 고른 상태, 열린 목록을 `aria-controls`로 가리킴). 누르면 달력 아래에 "11월 20일 · 지원 2건" 목록이 열리고, 같은 날짜를 다시 누르거나 닫기 버튼으로 접는다. 다른 날짜를 누르면 그 날짜로 바뀐다. 지원이 없는 날과 미래 날짜는 버튼이 아니다.
- 목록 행: 회사·공고명, 사이트 배지, 현재 단계. 누르면 홈의 다른 카드와 같은 상세 패널이 열리고, 닫으면 누른 행으로 포커스가 돌아온다. 단계는 낙관적 반영 목록에서 읽어 패널에서 바꾸면 바로 반영된다.
- 고른 날짜는 브랜드색 테두리다. 오늘을 고르면 오늘의 검은 테두리 대신 브랜드색을 쓰고, 오늘 표시는 `aria-current="date"`로 남는다.
- 말풍선(#184)과의 관계: 마우스를 올리면 그대로 보인다. 지원이 있는 날(버튼)은 키보드 포커스(`focus-visible`)에서만 말풍선을 보이고, 클릭·탭으로 생긴 포커스에는 보이지 않아 목록과 겹치지 않는다. Tailwind v4의 hover 변형은 hover가 되는 기기에서만 적용되므로 터치 화면에서는 탭하면 목록만 열린다. 지원이 없는 날은 전처럼 탭하면 말풍선("지원 없음")이 보인다.
- 데이터: `CalendarDay.applicationIds`(`companies`와 같은 순서)를 더했다. 목록은 이 ID로 지원을 찾고, 삭제 등으로 비면 그리지 않는다.
- 지원보드의 상세 버튼(기다리는 목록·중복 보기·칸반 카드)은 그대로 둔다. 홈 달력이 기록으로 가는 새 입구다.
