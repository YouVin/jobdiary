## 검증 공간

원본 애플리케이션 작업 폴더에서 테스트나 빌드를 실행하지 않고 별도 공간을 사용했다.

```text
C:\jobdiary-extension\release\monorepo-prep\2026-11-04\
  backups\     # 소스 압축본, 미커밋 패치, Git bundle, 해시 목록
  extension\   # 마감일 작업이 포함된 익스텐션 검증용 복사본

  logs\        # 테스트·빌드·Git bundle 검증 로그
```

위 자료는 `release/` 아래의 로컬 전용 자료이며 Git에 포함되지 않는다.
원본 두 저장소의 작업 브랜치·인덱스를 변경하거나 원격에 푸시하지 않았다.
원본 익스텐션의 기능 소스도 수정하지 않았다. 결과 기록을 위해 진행 계획과 이 문서만 작성·갱신했다.

백업 파일:

| 파일 | 내용 |
| --- | --- |
| `extension-history.bundle` | 원본 저장소의 Git 참조와 이력. `git bundle verify` 통과 |
| `extension-head.zip` | HEAD의 추적 소스 |

## 환경과 경고

- 웹앱 빌드에는 원본 `.env.local`을 복제본에 복사해 사용했다.
  템플릿 기준 필요한 키 2개가 모두 있는지만 확인했으며 값을 출력하지 않았다.
- `.env.local`은 복제본에서도 Git ignore 대상이다. 소스 압축본과 Git bundle에는 포함하지 않았다.
- npm의 사용자 디렉터리 접근과 의존성 설치·실행은 필요한 명령에 한해 샌드박스 밖에서 수행했다.
  Git 소유권 예외도 해당 명령의 정확한 복제본 경로에만 적용했고 전역 설정은 변경하지 않았다.
- Next.js는 복제본의 Git 루트 밖에 있는 원본 익스텐션의 `package-lock.json`을 무시했다는 경고를 냈다.
  빌드는 성공했다. 3단계에서 실제 모노레포 구조의 lockfile과 Turbopack 루트 판정을 확인한다.
- 실제 로그인한 Chrome에서의 수집·마감일 보충·웹앱 가져오기는 이번 자동 검증에 포함하지 않는다.
  해당 확인은 4단계에서 이어간다.
