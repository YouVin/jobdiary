# 공고 마감일과 자동 탈락 분류

현재 구현 기준: 2026-10-15 (#85).

지원 내역의 `deadlineAt`은 선택적인 `YYYY-MM-DD` 날짜다. 추가·수정 화면에서 직접 입력하며, 빈 값은 상시채용 또는 마감일 미확인으로 취급한다. 익스텐션 응답에도 선택적으로 허용하지만, 현재 익스텐션이 사이트에서 마감일을 수집하는 기능은 [별도 이슈](https://github.com/YouVin/jobdiary-extension/issues/60)다. 익스텐션 원본에는 `viewed`가 있지만 현재 웹앱의 저장 계약에는 열람 여부가 없어 이번 규칙에 사용하지 않는다. 기존 지원을 다시 수집해도 마감일을 포함한 기존 행은 갱신하지 않는다.

한국 날짜 기준으로 **마감 다음 날** 대시보드를 열었을 때도 상태가 `지원완료`인 건만 `탈락`으로 바꾼다. 마감 당일, 마감일 없음, 서류·면접 등 진행 중인 건과 이미 종료된 건은 변경하지 않는다. 과거 마감일을 새로 저장하는 경우도 같은 규칙을 적용한다. 여러 탭에서 동시에 열어도 DB의 현재 상태와 마감일 조건을 만족하는 행만 갱신한다. 자동 분류된 행은 `statusSource='deadline'`으로 구분하고 카드에 근거를 표시한다. 실제 기업의 불합격 통보를 확인한 결과가 아니며, 이번 웹앱 규칙은 열람 여부를 판단하지 않는다.

자동 분류는 대시보드 조회 시점과 대시보드를 열어 둔 채 한국 날짜가 바뀐 뒤 다시 활성화될 때 실행한다. 열린 탭은 1분 간격으로 날짜 변화를 확인한다. 페이지를 열지 않는 동안 서버 백그라운드 작업은 돌지 않는다. `지원완료`로 유지하고 싶으면 분류 전에 마감일을 비우거나 수정해야 한다. 이미 자동 분류됐다면 상태와 마감일을 함께 수정할 수 있다. 사용자가 직접 다른 상태로 옮긴 건은 자동 분류하지 않는다.

배포 순서: [`deadline_at` 및 상태 출처 마이그레이션](../supabase/migrations/20261015102447_application_deadline_auto_rejection.sql)을 대상 Supabase 프로젝트에 적용한 다음 웹앱을 배포한다. 저장소에 마이그레이션 파일이 있다고 DB에 자동 적용되는 것은 아니다.
